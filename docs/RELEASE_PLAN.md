# Следующая проверяемая версия

26 ноября 2026. Выполняем через Gemini API, без дообучения. Публикация — приватный GitHub, ветки main и submission.

## Условия завершения

1. Восемь существующих сценариев: ожидаемые конфликты найдены с правильными источниками, исправленные документы не получают замечаний. Повторить ключевые случаи; сохранять все попытки, в том числе неуспешные.
2. Выделение требований исключает связки, заголовки таблиц и незаполненные служебные шаблоны. Обязательства и исходные ID сохраняются.
3. Проверка доказательств переносит различия оформления цитат, но не подменяет слова исходника. Повторные причины объединяются; разные дефекты сохраняются.
4. Дополнительный набор из восьми документов фиксируется до изменения анализа. Проверяется после выбора кандидата; если результаты влияют на доработку, набор больше не называется отложенным.
5. Экран локального ревью: загрузка Markdown/PDF, прогресс и ошибка, замечание с цитатами, решение аналитика с сохранением, скачивание отчёта и сравнение двух проверок. Ключ остаётся на сервере; документы не попадают в Git.
6. Сравнить время, запросы и качество с предыдущей версией и одним запросом Gemini. Ускорение принимается только вместе с проверкой качества.
7. Подготовить протокол пилота для 2–3 людей, пустую форму наблюдений и сценарий защиты. Реальное участие людей не подменяется автоматической проверкой интерфейса.
8. Финальный код, входы, отчёты, демонстрация и манифест согласованы; повторный запуск из свежей копии, публикация и проверка удалённых файлов.

## Приоритет

Сначала качество и измерение. Затем экран ревью, сравнение версий и пилот. После этого проверка пользовательского пути, демонстрация и публикация. Контрольные результаты не редактируются вручную.
